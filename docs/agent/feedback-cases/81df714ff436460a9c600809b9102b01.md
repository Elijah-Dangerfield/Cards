## Working theory
Default cosmetics (`felt_default`, `cardback_default`) are seeded into the user's *inventory* by the server (`StarterInventory.kt` / `PostgresProfileRepository.seedStarterInventory`, ~L299-309) but **no equipment row is ever written for them**. The profile screen derives "equipped" purely from the equipment table: `MyItemsViewModel.ownedItems` sets `isEquipped = item.productId in equippedIds` (~L240) where `equippedIds` comes from `EquipmentRepositoryImpl.observeEquipped()` → `EquipmentDao` `SELECT * FROM equipment WHERE is_equipped = 1`. With no equipment row for a default, `isEquipped` is false, so `OwnedCosmeticTile` (`ProfileScreen.kt` ~L941, `showEquippedBadge = item.isEquipped && item.isEquippable`) never renders the equipped badge for the default felt/card back. Fix: treat a default item as implicitly equipped when it's in inventory but no other item of that slot is equipped — either in the `ownedItems` join (preferred; `Equipment.kt` L6-14 already documents that each surface owns its implicit-default rule) or by seeding default equipment rows server-side at profile creation. The `ownedItems` fallback is the lower-risk client-only fix.

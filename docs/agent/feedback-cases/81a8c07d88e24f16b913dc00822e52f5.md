## Working theory
The TestFlight upgrade wiped the persisted Supabase auth session (supabase-kt session storage did not survive the app update), while the app's own DB/cache survived — boot found the cached anonymous profile 087ac8d1 but no token. Because the account was anonymous there were no credentials to re-auth with, and `GuestSessionHealer` (MINT_FROM_PENDING) silently created a **new** guest instead of stopping, so the user watched his balance/XP get "reset" — the data actually still lives on 087ac8d1, unreachable. His recovery attempt (Apple sign-in, hide-my-email) minted a third account. Fixes needed: (1) make the session survive upgrades — check where supabase-kt persists the session on iOS (keychain vs a storage location invalidated by update) and add an upgrade-path test; (2) when a cached profile exists but the session is gone, never silently mint a fresh guest over it — surface an explicit recovery/sign-in flow; (3) longer-term, push account linking so beta testers aren't anonymous-only. Also explains why the InventorySync dropped his founding-member badge as "orphan". The equipment/badge row and old wallet are recoverable server-side by an admin merge of 087ac8d1 → his chosen account if desired.

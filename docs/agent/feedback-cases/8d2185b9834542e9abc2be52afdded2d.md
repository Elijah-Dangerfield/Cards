## Working theory
This is exactly MP-21 — when the opponent leaves and the hand auto-resolves, the client routed Home on the `OpponentsLeft` path without reconciling the wallet, so the won pot stayed invisible until a manual background/foreground fired `ChipsSync`. The fix shipped in PR #74 (merged 2026-06-26 07:29, in develop): `PlayPokerViewModel` now calls `reconcileWalletAfterGame()` inside the `session.opponentsLeft.collect { … }` block (and on `ClosedReason.MatchOver`), the same reconcile `leaveAndReconcileWallet()` does for user-initiated leaves. The report build string `cardse@0.1.0+1` is unchanged from the pre-#74 builds and the report landed at 21:00, so the tester was on a pre-#74 build. No new defect — re-test on a current build. The user's secondary ask (a toast / dialog showing "you won N" on leave) is a real UX enhancement layered on the same flow; it is NOT covered by MP-21 (which only fixes the silent balance) — captured as a backlog one-liner.

## Working theory
StoreKit transactions are Apple-account-scoped and survive app reinstall, so every fresh install replays the tester's stuck orders. On a fresh install the account is a new anon userId, so the receipt validates against a different owner than it was minted under → server rejects (receipt_rejected / apple_account_mismatch flavour of BILL-11). Compounded by CARDS-96 (catalog SKUs unrecognized). Not related to the onboarding work on `develop`; it's billing + the AUTH-19 identity churn. Fix: gracefully finish/acknowledge replayed-or-unmatched transactions instead of surfacing a failure loop, and reconcile receipt ownership across the anon→claimed rollover.

## Working theory
When one human crashes/disconnects mid-hand, the room enters a state where `DELETE /rooms/{code}/me` returns 409 Conflict for the remaining human (cannot leave while the hand/settlement is in flight), so "leave" silently fails and the back button looks broken. It only clears once the server tears the hand down ~90s later. Fix: the leave endpoint should accept (or queue) a leave during post-crash settlement instead of 409-looping, and the client should not present a dead button — show progress or allow forfeit-leave. Related to the existing MP leave/forfeit work (MP-1) and the leave-→-Home todos, but this is a distinct server-side 409 block.

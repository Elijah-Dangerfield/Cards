## Working theory
Real bug: **multiplayer hands never run the hand-end progression path, so XP is not awarded** (and player-stats + the level-up/achievement celebration are also skipped). `RemotePokerSessionFactory.create` ([RemotePokerSessionFactory.kt](../../../features/room/impl/src/commonMain/kotlin/com/cards/features/room/impl/session/RemotePokerSessionFactory.kt):74-89) constructs `RemotePokerSession` **without** wiring the `onHandEnded` callback the VM passes. Its comment claims "onHandEnded fires through the VM's normal GameEvent collector → handleHandEnded path," but the `GameEventReceived` branch in `PlayPokerViewModel.handleAction` (lines 665-711) only accumulates play-style + projection — it never calls `handleHandEnded`, which is the only caller of `progressionRepository.awardForHand` / `recordPlayerStat` / the achievement reveal. `LocalBotsSession` invokes `onHandEnded` explicitly (line 454), which is why solo bots DO award XP (PROG-3's log shows "Awarded 5 XP"). Achievements still appear in MP only because they're pulled server-side via `AchievementSync`. Fix: invoke `onHandEnded` from the remote session on each `HandEnded` (mirror `LocalBotsSession`), or call `handleHandEnded` from the MP `GameEventReceived` branch on `GameEvent.HandEnded` — with a failing test that plays an MP hand and asserts XP/player-stats advanced. Confidence high; the account-delete is a red herring (the fresh account simply makes the "still 0" obvious). Distinct from PROG-3 (CARDS-4V), which is the celebration UI for an award that *did* fire in solo bots.

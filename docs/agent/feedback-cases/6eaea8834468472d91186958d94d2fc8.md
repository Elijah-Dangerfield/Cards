## Working theory
The arithmetic is **correct**: +50 won in hand 1, −25 lost as the small blind forfeited at the start of hand 2 = +25 net. No chip bug. The user simply didn't realise hand 2's blind had already been posted when they left, so +25 surprised them. So the "only 25" complaint is no-action. BUT the user's repeated, explicit ask — "show how much the user will win or lose in the leave-confirmation dialog … make people super in control of their money" — is a legitimate, recurring UX gap (CARDS-57 from the same player says the same thing about losing a posted blind on leave). File one UX todo: surface the net settle delta (and a note about a posted blind being forfeited) in the leave-confirm dialog. The secondary ask ("let people leave before the next hand starts so they don't post a blind") is a bigger design question — mention it in the todo as a directional option, not a requirement. The leave-confirm surface today is `LeaveBotsConfirmDialog` ([ui/LeaveBotsConfirmDialog.kt](../../../features/room/impl/src/commonMain/kotlin/com/cards/features/room/impl/ui/LeaveBotsConfirmDialog.kt)); the MP leave-confirm path needs the same treatment.

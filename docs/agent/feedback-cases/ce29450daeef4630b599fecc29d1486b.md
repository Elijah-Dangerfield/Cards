## Working theory

screen, but a rejected join still enqueues a navigation `batch` (visible after every
`JoinCodeRejected`), producing a flicker/recomposition that reads as a navigation
event rather than an in-place error toast/inline message. The error should surface
in place with no route batch — keep the PrivateJoin screen visually still and just
show the "room not found" affordance. Worker should check the `JoinCodeRejected`
handler / PrivateJoin route wiring in the room feature (whatever enqueues the
`DelegatingRouter` batch on reject). Confidence medium-high — the log clearly pairs
reject → navigation batch.

## Working theory
Supabase anti-enumeration returns a fake "success" (no session, no email) when signing up with an already-registered email, so the client can't distinguish it and shows VerifyEmail, which then auto-advances (the "1-second flash") instead of saying "already registered — sign in." If the tester reused their own already-confirmed email against a live anon session, refreshSession found emailConfirmedAt set → immediate Home, matching "continued to the app." **Cross-check with recent work:** on `develop`, Option B re-routes VerifyEmail (new→onboarding / returning→Home) and the SessionExpired-on-no-session fix changes the *no-session* variant to bounce to sign-in — neither adds a clear "already registered" message, and the new landing "Sign up with email" button makes this path far more prominent. Fix belongs with/before that merge.

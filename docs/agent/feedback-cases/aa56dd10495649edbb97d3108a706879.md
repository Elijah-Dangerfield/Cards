## Working theory
The pending-auth/OAuth handle that `completeOAuthRedirect` looks for is held **in memory only**. When the user kills the app mid-signup, that handle dies with the process. On relaunch via the confirmation deep link (`cards://login-callback`), `completeOAuthRedirect` finds no pending handle and logs "ignoring stray redirect" — so the confirmation token in the link is never exchanged for a session and the user is dropped, still unauthenticated, with no feedback. Fix: the confirmation/callback deep link should establish a session from the token carried in the link itself (Supabase can exchange the code without a prior in-memory handle), OR persist the pending-signup handle across cold start so the redirect is honored after a kill. Pairs with AUTH-25 (the pre-kill routing). Confidence high — the "no pending OAuth handle — ignoring stray redirect" log line directly matches the user's account.

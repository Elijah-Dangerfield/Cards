## Working theory
MP chip escrow + persistence shipped in #67, but the wallet settlement is still client-derived and there is no server-side (or test-enforced) conservation invariant on an MP game. The two clients each computed their own wallet delta from their own view of buy-in/escrow/payout, and the two deltas don't sum to zero (+2000 net), so chips were minted. Likely the buy-in debit and the payout credit use different bases (e.g. a default/zeroed buy-in on one side — see the related $0-buy-in bug MP-10), or the loser's debit and winner's credit are computed independently rather than from one settlement record. Fix: make the server the authority on MP settlement (debit buy-in on seat, credit pot on payout, single ledger entry per seat per game) and add an integration test that plays a full MP game and asserts `sum(wallets_after) == sum(wallets_before)`. The reporter explicitly asks for exactly this test. High confidence it's a real invariant violation; exact arithmetic source needs the settlement code read.

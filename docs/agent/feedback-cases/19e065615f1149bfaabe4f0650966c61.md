## Working theory
On an offline cold boot, `AuthRepository` can't reach Supabase to resolve/refresh the anonymous session (5 attempts exhausted; `GuestSessionHealer` SKIP_OFFLINE), so there's no live session in memory even though the user is onboarded and has a valid anon account. The start-a-game gate reads "no authenticated session" and surfaces the generic **"account needed"** copy — the wrong message for an offline-but-registered guest, and it blocks solo/practice play that shouldn't need the network. Fix directions: (a) persist/restore the guest session locally so an offline cold boot still has identity for solo play; and/or (b) branch the start-game gate on connectivity — show an honest "you're offline" state instead of "account needed" — and allow offline solo bots. Related but distinct from the backlog "Offline-aware retry / deferred queue" item (that's about write retries, not this gate/copy). Real blocked-play + misleading error → P1.

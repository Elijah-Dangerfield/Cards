## Working theory + fix
The profile cosmetic shelves use `EdgeToEdgeRow`, whose `escapeHorizontalScreenPadding` layout modifier is meant to bleed the row full-width while re-insetting item 0 via `contentPadding` to line up with the section header (both at D600 = 14dp). Measured gap in the screenshot ≈ 14dp = exactly D600, i.e. the start inset was being dropped. Root cause: the modifier reported the *expanded* (`maxWidth + 2*inset`) width to the parent; on iOS the parent then treated the row as an oversized child and dropped its start inset entirely, so item 0 landed at the physical screen edge. Fix: report the *in-flow* (un-expanded) `constraints.maxWidth` to the parent and keep drawing shifted left by the inset — the parent positions the row normally, `contentPadding` re-insets item 0 to match the header, and the row still bleeds off the right edge. `libraries/ui/.../components/EdgeToEdgeRow.kt`. Fixes every `EdgeToEdgeRow` (profile shelves + home strips).

## Working theory
The client chip balance is a local DB row (`ChipsRepositoryImpl` / `chipsDao`) refreshed only by `ChipsRepository.sync()`. That sync runs on cold boot / foreground (`UserScopedSyncCoordinator`) and on user-initiated leave (`PlayPokerViewModel.leaveAndReconcileWallet()`, fired from `LeaveTable` / `LeaveGameFromBust` — added for CARDS-3C). When the *opponent* leaves and the hand auto-resolves, the `session.opponentsLeft` collector (PlayPokerViewModel ~line 204) only emits `PlayPokerEvent.OpponentsLeft` to auto-route Home — it never reconciles the wallet. So the lost-pot settlement stayed invisible until the manual background/foreground triggered `ChipsSync`. Fix: reconcile the wallet on the auto-terminal MP paths (opponentsLeft / match-over / settled HandEnded), the same way `leaveAndReconcileWallet()` does for user-initiated leaves. High confidence; root cause confirmed in both client breadcrumbs and server logs.

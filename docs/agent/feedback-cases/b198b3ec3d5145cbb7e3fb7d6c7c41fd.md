## Working theory
Apple's App Store Server API requires `appAppleId` when verifying a transaction against the **Production** environment, and TestFlight builds produce production-signed transactions. The client's redeem request doesn't carry `appAppleId` (or the server doesn't have it configured), so every TestFlight chip-pack purchase 400s and is left uncredited — StoreKit considers the purchase complete, so the user paid (sandbox) and got nothing. 100% reproducible failure for all TestFlight/production purchases, twice in this session. Fix: send/configure `appAppleId` on the redeem path (verify against both prod + sandbox per Apple's recommended fallback), retry uncredited orders on next launch, and do the owner's UX asks — purchase-in-flight loading state on the shop and a full error dialog (not a toast) on failure. Relates to BILL-6 (sandbox purchases recorded as real).

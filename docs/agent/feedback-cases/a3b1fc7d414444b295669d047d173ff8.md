## Working theory
The create-room form's buy-in **slider defaults to 0** (its initial value isn't seeded to the minimum/default stake), so a user who taps Create without dragging the slider creates a room with buy-in 0 — both reporters independently hit this. A $0-buy-in MP room is meaningless and almost certainly feeds the wallet-conservation bug (MP-13): if one seat's buy-in is 0, the buy-in debit and payout credit no longer net to zero. Fix: seed the create-room buy-in slider to a sensible non-zero default (e.g. the lowest tier) and/or block Create at buy-in 0. Distinct from the backlog "$0 buy-in after sole-human-left rebound" item, which is a post-leave stale-snapshot symptom; this one is the creation-form default. High confidence — two independent reports, clear repro ("unless I move the slider").

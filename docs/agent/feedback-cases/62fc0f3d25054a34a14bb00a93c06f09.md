## Working theory
"Only medium works" is a symptom, not the defect. The small (…803) and large (…555) StoreKit transactions were created in an earlier session under the guest identity `52f3f9c1`, so their `appAccountToken` is `52f3f9c1`. After the AUTH-19 account upgrade the caller is now `6f0a900c`, and `AppStoreReceiptValidator.validate` (`apps/server/.../data/AppStoreReceiptValidator.kt:122`) rejects any receipt whose `appAccountToken` != caller → `apple_account_mismatch` → 400 `receipt_rejected` → uncredited, retried forever. Medium succeeds only because it was (re)purchased fresh under the current identity. Fix direction: accept receipts whose `appAccountToken` belongs to any identity in the install's account-upgrade lineage (or migrate/re-stamp the token on upgrade). Direct downstream of AUTH-19; the client-side false-"pending" messaging on these same 400s is BILL-12 (case 2f2ed445…). Sandbox/beta only today, so no real-money loss yet, but it strands purchases and must be fixed before real-money go-live.

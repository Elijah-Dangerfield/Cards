## Working theory
Heads-up, the loser busts to 0. The server (correctly) won't start a new hand because only one player has chips, so it rejects RequestNextHand with `not enough players with chips for next hand`. But the UX has no resolution: the **winner's "next hand" button does nothing** (silent repeated rejection, no message), and the **busted player just sees "you're out of chips"** with no rebuy/leave/you-won-the-match affordance. The hand effectively deadlocks until someone force-quits (which is what happened — the busted player left and the room closed). This is the heads-up terminal-state of the long-running hand-end-stall family (CARDS-25, CARDS-16) but specifically the *legitimate bust* case, not a stall bug: the server is right, the client needs an end-of-match / rebuy flow. Fix: when next-hand is rejected for `not enough players with chips`, show a match-over result (winner takes the table) or offer the busted player a rebuy, instead of a dead button + bare "out of chips". High confidence on the symptom; product call needed on rebuy-vs-match-over.

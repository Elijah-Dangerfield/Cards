## Working theory
The signup network call to Supabase prod (`/auth/v1/signup`) exceeded the client's 10s timeout → `SignUpOutcome.NetworkError` → bare "signup failed" with no retry. Most likely the built-in Supabase email sender is slow / rate-limited (custom SMTP still unconfigured, and the tester fired repeated signups across fresh installs in minutes). Fix: retryable error UX + a timeout sized for the confirmation-email round trip, or decouple the send from the signup response. Distinct from ENG-30 (that was a TLS bind failure; here the request reached Supabase and timed out).

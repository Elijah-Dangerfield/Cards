## Working theory
Real bug and a regression of the exact symptom `reconcileWalletAfterGame` was built to kill (its own doc comment cites CARDS-3C/4B: "lost a game but the balance didn't update until I backgrounded and foregrounded"). On the **host's leave-via-top-back-button** path the reconcile sync isn't firing: the log shows the `go back` → Home transition with no `ChipsSync` and no `LeaveCashOutNotifier` toast, and the settled 9975 only lands on the next `OnForeground`. `reconcileWalletAfterGame` / `leaveAndReconcileWallet` ([PlayPokerViewModel.kt](../../../features/room/impl/src/commonMain/kotlin/com/cards/features/room/impl/PlayPokerViewModel.kt):601-641) clearly works for the in-screen Leave action and the auto-terminal signals, but the system back-gesture / top back-arrow leave on the room owner bypasses it (the VM is cleared / popped before the reconcile runs, or back doesn't route through the leave handler). Fix: make every leave path — including system back and the top back-arrow — funnel through `leaveAndReconcileWallet` before the screen pops, with a failing test that pops the play screen via back and asserts a post-leave wallet sync fired. Confidence high. Related to the open ROOM-2 "in-room Leave button unreliable vs top back button" (CARDS-47) — same theme of two leave paths behaving differently — but this one is specifically the *wallet reconcile* not the navigation.

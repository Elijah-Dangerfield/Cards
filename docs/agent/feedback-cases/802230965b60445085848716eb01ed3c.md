## Working theory
The ~15.1s socket lifetime is a signature, not noise: Ktor's WebSockets plugin defaults to `timeoutMillis = 15_000` with pings **disabled** (`pingPeriodMillis` unset). With no ping/pong traffic, every room socket is killed by the server 15s after the last frame and the client immediately reconnects (~450ms), flashing the "lost connection" banner each cycle. Fix on the server: set `pingPeriod` (e.g. 10s) — and sanity-check the client engine's own timeout too. Optionally debounce the banner (only show after N hundred ms of downtime), but the keepalive is the real fix. This likely affects every quiet MP table on both platforms; the prod iOS sockets in case 4587d9b2 show the same pattern is masked only by traffic.

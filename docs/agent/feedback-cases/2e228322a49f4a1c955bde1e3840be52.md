## Working theory
When a heads-up MP hand ends because the opponent times out (auto-fold) preflop, the server sends only the terminal `game_state … street=Complete acting=null` snapshot to the non-acting player — no `ActionTaken(Fold)` / `HandEnded` / `PotAwarded` events the client can react to. The client therefore shows a dead table: no acting seat, no reveal, no pot-award, no "next hand" affordance, and the BB player who never got to act is left staring at a frozen board. Same family as MP-25 (CARDS-5F: showdown jumps Complete→next with no reveal) but the trigger here is an opponent fold/timeout. Fix: drive an explicit hand-ended/winner presentation (and an advance-to-next-hand path) off the `Complete` snapshot even when no intermediate events arrived, and surface the opponent-timeout-fold. Confidence high; root cause confirmed from client log + client-state + server log.

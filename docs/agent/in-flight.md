# In-flight

## feat(onboarding): step-progress chip + OS-back stepping

**Problem:** Onboarding had no sense-of-place indicator and no `BackHandler`, so a hardware/gesture back exited the flow instead of returning to the prior step.
**Approach:** Added a "Step N of 3" `StatusPill` (reused the DS pill rather than a one-off box) aligned `TopCenter` in the host `OnboardingScreen` so it overlays every step uniformly, and a `BackHandler` enabled on every step except `Welcome` that routes to `OnboardingAction.Back` — mirroring the in-UI Back button (the VM's `handleBack` already steps HowItWorks→PickIdentity→Welcome and no-ops on Welcome). Welcome stays the only exit point.
**Reviewer notes:** The chip uses `surfaceHigh` + `contentSecondary` at `Label.L300` and sits on the same top line as the existing Back/Skip ghost buttons via `D300` top padding — vertical centering vs. those buttons wasn't eyeballed in Studio (no rendering env here), so a small baseline nudge may be wanted on a visual pass. `BackHandler` emits a "use NavigationEventHandler instead" deprecation warning, consistent with existing usage in `PlayPokerScreen`/`BlockingErrorScreen` — left as-is to match the codebase pattern. No new tests (screen is UI-only; existing `@Preview`s now render the chip on all three steps).

## feat(lobby): confirm before backing out of a seated room

**Problem:** The lobby's top-bar back and OS back just called `onBack` (gated only by `isBusy`), silently dropping the seat without notifying the server — part (1) of the "don't let players silently abandon an active game" item.
**Approach:** While `isInRoom`, intercept both back paths (top-bar `onNavigateBack` and a `BackHandler`) to raise a "Leave the room?" confirm (DS `Dialog` title/description overload). Confirm routes the exit through `LobbyAction.Leave` (so the server is notified via the VM's `appScope` call, which survives the screen pop) then `onBack()`; cancel dismisses. Chose to dispatch `Leave` rather than a bare `onBack` so the confirmed exit drops the seat cleanly instead of leaving a zombie seat — the alternative (confirm-then-just-navigate) keeps the silent-abandon bug for the server's view.
**Reviewer notes:** Idle (not-seated) back is unchanged — confirm only fires once seated. The confirm is screen-local `remember` state, not `LobbyState`, so it isn't preview-able from the existing state-driven `@Preview`s and has no VM unit-test surface; behavior verified by compile only (no Compose UI test harness here). Part (2) of the item (reactive Home active-room flow) is untouched and rewritten as its own todo bullet.

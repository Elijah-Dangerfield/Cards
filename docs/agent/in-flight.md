Test-first: added a red-then-green route test for the lazy-seed path plus a guard for the no-manifest 409.
**Reviewer notes:** Judgement call — I chose lazy-seed-from-manifest over relaxing the FK (keeps the rule→flag invariant and a clean resolve union; rejected FK-relax for splitting the source of truth). The seed writes an audited `create_flag` row with the manifest default, which is honest (it's the shipped value, not an operator guess) and sets ENG-5 up to relabel that layer as a read-only "shipped default" vs an explicit "global override". Sliced ENG-5: its server-side lazy-create sub-part is done here, so I trimmed that clause; the UX reframe (read-only in-code default, relabel base editor) remains under ENG-5.

## feat(gameplay): add a Table speed setting that scales deal/reveal animations (GAME-6)

**Problem:** A tester asked to speed the table up, including an "instant" mode that skips the deal/reveal animations. The play screen had one fixed pace with the timings hardcoded as magic numbers scattered across `BoardArea` and `PlayerArea`.
**Approach:** Added a `GameSpeed` enum (Normal/Fast/Instant, with an `animationScale` of 1.0/0.5/0.0) to `AppData`, surfaced as a "Table speed" picker in Settings → Gameplay mirroring the existing Bot speed pattern end-to-end (AppData field → `appCache.update` callback → `ProfileSettings` → picker). Rather than thread a speed param through every animation, I introduced a `TableTempo` value + `LocalTableTempo` composition local (defaults to Normal, so previews/tests need no provider — the pattern AGENTS.md prescribes for cross-cutting subtree state). `PlayPokerScreen` provides it from `state.gameSpeed`; the hole-card and board-card animators read it to scale their `delay()`s and `tween()` durations, and `isInstant` jumps cards straight to settled (the same branch previews already used). Test-first wasn't applicable (new feature, not a bug), but `TableTempoTest` pins the scaling math: Normal unchanged, Fast halved, Instant collapses every delay/duration to zero.
**Reviewer notes:** Judgement call on the option set — I shipped Normal/Fast/Instant (Fast = 0.5x) as the recommendation names; rejected a continuous slider as overkill for a casual setting. The `gameSpeed` is wired through the `PlayPokerState` settings-mirror collector, so it applies live to both bot and MP tables (same path as `botSpeed`/`turnFeedback`). I scoped this to the **deal + reveal** animations (the dominant, tester-visible delays); the chip-stack odometer and pot count-up still play at fixed pace because they live in shared `:libraries:ui` DS animators that the DS deliberately animates for identity-bearing content — scaling those needs a default-preserving change inside the primitive, which I deferred.
**Deferred:** Chip-stack / pot count-up scaling (the "chip-move" half of the tester's ask) → appended to `docs/backlog.md` ("Scale chip-stack and pot count-up animations with the Table speed setting").

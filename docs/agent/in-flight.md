## refactor(room): migrate tutorial narration + scripted-hand copy to resources

**Problem:** The scripted tutorial (`TutorialScript`, `TutorialModel`, `TutorialNarrationStep`, `TutorialPokerScreen`) still owned the bulk of the user-facing tutorial copy as inline `String` literals — three basics narration cards × {title, body, cta}, eleven tableau coach marks × {title, body, cta}, the HandRanks hero rows, the Actions hero rows, the per-section step-counter format, and the "Skip basics" text-link button. Without lifting these, the strings sweep can't claim `:features:room` is done even after the rest of the room migrated last night.
**Approach:** Lifted `CoachMark.title/body/ctaLabel/bullets`, `TutorialSection.displayName`, and `NarrationHero.topBarLabel` from `String`/`String?` to `StringResource`/`StringResource?` so the static `TutorialScript.steps` catalog stays a non-Composable `val` — same shape as the prior `BetPreset.labelResource` / `RankingEntry.name`+`tagline` migrations earlier in the cycle. Resolved via `stringResource(...)` at the `NarrationStep` / `CoachMarkBanner` / `StepCounterPill` / `BulletList` callsites. The per-section step-counter format `"Step %1$d of %2$d · %3$s"` became `tutorial_step_counter` with positional args. Two `CoachMarkBanner` previews that used inline literals now reach into `TutorialScript.steps` for canned coach data — they were illustrative anyway and the script has equivalent narration + action-prompt examples already. Bot tutorial names (Ada / Ben / Cleo) and the human "You" displayName stay inline because §D parks bot-name localization for V1.x/V2. The tutorial-side `humanHandLabel: String?` ("Pair of aces" etc.) also stays inline since that field's downstream consumer in real gameplay is the engine-computed hand-evaluator output, and migrating the field across both paths is its own slice.
**Reviewer notes:** The `TutorialSection` enum constructor parameter changed from `String` to `StringResource` — clean if you read it as "the displayName is *the resource key*, not the resolved text." If anywhere in nightly Reviewer flows wants the resolved display name in a non-Composable context (analytics tag, log line) they'd need `getString(section.displayName)` from a suspend scope. I grepped and found no such consumer today.
**Deferred:** Tutorial leftover surfaces (`AchievementUnlockedDialog`, `TutorialLeaveDialog`, `TutorialReadyScreen`) — those carry their own dialog copy and were out of scope for this slice; logged in `docs/todo.md` as the next tutorial chunk.

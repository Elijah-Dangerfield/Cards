## test(integration): play three consecutive full hands to showdown over the wire

**Problem:** Owner review of the `:apps:integration` coverage flagged it as thin — `MatchmakingPlayTest` already plays full hands for the public/server-dealt path, but the friend-game (host-driven via `StartHand` + `RequestNextHand`) path only had a single preflop-fold multi-hand test and no end-to-end "deal → preflop → flop → turn → river → showdown → next hand" loop.
**Approach:** New `MultiHandWireTest.threeConsecutiveFullHands_dealThroughShowdown_chipsConserved` plays three consecutive full hands over the real wire on the heads-up friend-game path: the host taps `StartHand` once, then `RequestNextHand` between hands; each hand is walked passively (check/call) to `BettingRound.Complete`, asserting five community cards (showdown reached, not a preflop fold), button rotation across hands, and per-hand chip conservation. Updated [`docs/testing-plan.md`](../testing-plan.md) Round 2 entry to cite the new companion test. Considered three-player coverage (`seatThreeAndConnect`) but it duplicates the existing `WireSidePotTest` plumbing without testing the host-driven boundary the owner called out; left out to keep the slice tight.
**Reviewer notes:** None — green locally on `:apps:integration:testDebugUnitTest`. The cursor-aware `playPassivelyToCompletion` accumulates buffered snapshots, so the same harness can drive consecutive hands without resetting `GameplaySession`; the test relies on that behaviour.

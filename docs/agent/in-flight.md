## fix(ui): render hosted dialogs in a top-most Popup so they clear bottom sheets (GAME-11)

**Problem:** The shake "sun" feedback dialog was occluded when opened over an open bottom sheet — Material's `ModalBottomSheet` renders in its own platform window that floats above the entire main Compose composition, including the App-root `DialogHost` where DS dialogs draw (CARDS-6Y).
**Approach:** Wrapped `DialogHost`'s hosted entries in an `androidx.compose.ui.window.Popup` (full-screen, focusable, non-clipping, and not self-dismissing — `DialogOverlay` still owns scrim/back/outside-tap). A popup only exists while entries do, so a dialog registered while a sheet is up opens its window *after* the sheet's and wins z-order. This lifts *every* DS `Dialog`/`BaseDialog` above sheets, not just feedback — the reporter's "should be a global setting" instinct, and the systemic fix. In `@Preview` inspection mode it falls back to inline rendering (Compose popups don't paint on the preview surface). Chose the DialogHost-wide fix over re-plumbing only shake→feedback because the latter leaves every other dialog able to hide behind a sheet; chose a popup over Box re-ordering because composition order can't beat a separate platform window. Decision logged (decisions.md 2026-07-01).
**Reviewer notes:** Not unit-testable — window z-order has no JVM-test surface, so this is verified by compile (Android + iOS Kotlin + `:libraries:ui:test` green) plus a `docs/QA.md` GAME-11 device check. Watch on device for: (a) the dialog scrim still dims the sheet and taps/back dismiss correctly, (b) status-bar/inset behaviour of the full-screen popup on both platforms, (c) no double-scrim when a dialog opens with no sheet present. All existing DS dialogs now route through the popup — broad blast radius, so a device smoke of a normal dialog (e.g. sign-out confirm) is worth it too.

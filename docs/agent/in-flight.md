## fix(server): deconflict player-stats endpoint path from /v1/me/stats (PROG-1)

**Problem:** The PROG-1 server slice (commit `3a18d0b4`, this same cycle) registered `GET /v1/me/stats` for the new player-stats snapshot, but that exact path was already taken by the lifetime distinct-opponents read in `meRoutes` (live, wired into `LifetimeStatsRepositoryImpl`). Two identical `get("/v1/me/stats")` registrations under the same auth block collide — Ktor attaches both to one routing node and the later registration (`meRoutes`, installed after `playerStatsRoutes` in `Application.kt`) wins, leaving the new player-stats GET unreachable. The PROG-1 client half can't fetch its snapshot until this is resolved.
**Approach:** Moved the new endpoints to their own namespace — `GET /v1/me/player-stats` and `POST /v1/me/player-stats/sync` — rather than touch the pre-existing `/v1/me/stats` lifetime read, which shipped first and is already in production client code. Picked `player-stats` over collapsing the two endpoints into one merged DTO because the lifetime distinct-opponents count is a server-derived read with no client write-ahead, whereas player-stats is the idempotent sync surface; merging them would entangle two unrelated read-path policies. Only the route paths + their doc comments changed; the repo, DTOs, migration, and tests are untouched (no test asserted the old path).
**Reviewer notes:** No route-level test exists for the player-stats endpoints yet (only the Postgres repo integration test + the MeRoutes fake), so this rename had nothing to update there. The PROG-1 client repo (still open) should target `/v1/me/player-stats`. Worth a glance: confirm no other in-flight branch hard-codes `/v1/me/stats` for the new snapshot.

## feat(stats): client write-ahead player-stats outbox + sync (PROG-1)

**Problem:** The server-authoritative player-stats endpoints existed but nothing on the client wrote to or read from them, so hand counters / no-bust streak / per-bot wins still lived only in `AchievementProgress.customCounters` — device-local, lost on account-switch / reinstall.
**Approach:** Shipped the **repository slice** of PROG-1, mirroring `PlayStyleRepositoryImpl` exactly: Room cache (`player_stats`) + outbox (`player_stat_events`) at DB v20, DAOs wired through `ProvideDaos` (incl. the `ClearableDao` multibinding so an account-switch wipes them), `PlayerStats` / `PlayerStatHandSummary` / `PlayerStatsRepository` domain types, the DTOs, and `PlayerStatsRepositoryImpl` (single-flight idempotent sync against `/v1/me/player-stats/sync`, snapshot cached for offline + instant render, `AppEventListener` for cold-boot / claim / warm-foreground sync). A finished hand records a stat row in `PlayPokerViewModel.handleHandEnded` via the new `PlayerStatHandSummaryBuilder`, which owns the order-dependent no-bust streak (seeded from the cached snapshot, incremented per survived hand, reset on bust). DB bump is destructive-fallback (pre-launch, no users to migrate). Sliced because the achievements-as-predicates refactor + stats-screen rewiring touch the live unlock path and are the riskier half — PROG-1 rewritten to describe that remaining work.
**Reviewer notes:** Two judgement calls. (1) `beatenBotId` carries a single bot per hand, but achievements credit *every* bot at the table on a win; the per-bot-wins DTO is single-keyed, so the builder picks the first distinct opponent — correct heads-up (the common case), a defensible single attribution multi-bot. If the server map should mirror the achievements' "win counts vs every bot" semantics, the DTO needs to become a list. (2) `vsBot` is derived from `context.opponentBotNames.isNotEmpty()`, so an MP-vs-bots hand counts toward `botHandsPlayed`; that matches how `creditMode` already downgrades such hands. The numbers aren't surfaced on any screen yet (the stats screen still reads achievement counters), so this commit is invisible to users until the deferred rewiring lands — no QA entry. New repo + builder tests green; `assembleDebug`, iOS Kotlin compile, and the touched room VM suites all pass.
**Deferred:** Stats-screen rewiring + achievements-as-predicates stay under PROG-1 in `docs/todo.md` (rewritten to describe exactly that).

## feat(config): JsonConfigValue<T> for structured (non-scalar) config

**Problem:** The config system only resolved flat dotted-path scalars (`FlagConfigValue`/`IntConfigValue`/…); variable-length structured data (the level ladder + reward table, future loot tables) couldn't be flattened into fixed scalar paths.
**Approach:** Added `JsonConfigValue<T>` in `:libraries:config` — resolves one path to its parsed config subtree, converts it back to a kotlinx `JsonElement` (`toJsonElement` inverse of the parse), and `decodeFromJsonElement` into a `@Serializable` model via a constructor-supplied `KSerializer<T>`. Decode failure or missing path falls back to the bundled `default` (soft-fail, so a malformed server value never bricks the client). Chose the `KSerializer` constructor param over reified `serializer()` so the base stays a plain abstract class with no inline/reified plumbing. Hidden from the QA dashboard by default (a JSON blob can't round-trip the per-key toggles, per the todo note). Pulled in `kotlinx-serialization-json` (runtime only — no compiler plugin needed for the base since it declares no `@Serializable` types).
**Reviewer notes:** Tests live in `:libraries:config:impl` commonTest (where the serialization plugin is already on) since `:libraries:config` itself has no test source set. Covered: nested-object decode, array decode, missing-path/empty fallback, undecodable-payload soft-fall-back, unknown-key tolerance, model-default for omitted optional field. The level-ladder todo's "Depends on: the JsonConfigValue config-lib extension" is now satisfied — left that item's wording untouched (curation surface).

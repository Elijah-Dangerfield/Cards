## feat(stats): recent-XP rows get source emoji, type-colored points, relative time

**Problem:** Recent-XP rows showed a plain label + uncolored `+N` and never said when the XP was earned.
**Approach:** Each row now leads with a per-`XpSource` emoji (🃏/🪙/👀/💪/🎯), colors the `+N` by source (content/teal/coral/info/success), and stacks an `earnedAgo(...).label()` relative timestamp under the points — reusing the existing day-granular `EarnedAgo` DS util the hint pointed at rather than building a parallel minutes/hours formatter. Source label strings were left as the pre-existing inline literals (out of scope; not new violations).
**Reviewer notes:** `EarnedAgo` buckets at day granularity, so several same-day events all read "today" — acceptable per the "earnedAgo-style" hint, but if the mock wants minute/hour precision that's a follow-up formatter. No new tests: the maps are exhaustive `when`s over `XpSource` (compiler-checked) and the relative-time factory is already covered by `FormatEarnedAgoTest`. Verified by module compile + `:features:progression:impl:testDebugUnitTest`.

## refactor(profile): converge shelf headers onto the DS SectionHeader

**Problem:** Home shelves used the DS `SectionHeader` (neutral secondary "See all", whole-row tap); Profile shelves used a private local `SectionHeader` with an accent-primary CTA action that only the action text was tappable — same pattern, divergent chrome.
**Approach:** Deleted Profile's local `SectionHeader` and routed both call sites (cosmetic shelves + the achievements grid) through the DS one. Chose to converge on Home's neutral treatment (one component, one visual: secondary trailing label, whole-row tap, `Heading.H800` title) rather than add an accent-CTA flag to the DS component — a flag would re-introduce the two-treatment divergence the item asks to remove. Trade-off: the "Shop ›" link loses its accent-primary color and becomes a neutral secondary label (still reads as a shop shortcut via the "›" + whole-row tap); the reviewer can course-correct if the spend-CTA was meant to pop. The achievements header's separate count + "See all" fold into one `"%1$d / %2$d · See all"` trailing label, matching Home's `"%d online · See all"` idiom.
**Reviewer notes:** Profile titles go `H700 → H800` as part of the unification (bigger, matches Home). Dead strings `profile_achievements_count` / `profile_achievements_see_all` removed (no other refs); added `profile_achievements_count_see_all`. Shop's own bespoke header (`ShopScreen.kt`) is a Column with NO see-all/CTA — a static section title, a different role — so it's intentionally left out of this convergence. No new tests (header rendering is UI-only; existing profile VM tests pass). Verified by `:features:profile:impl:compileDebugKotlinAndroid` + `testDebugUnitTest`.

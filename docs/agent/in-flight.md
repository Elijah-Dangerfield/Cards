## feat(server): persist GameSession events to Postgres before broadcast

**Problem:** Todo §B0's first bullet — every emitted `GameEvent` needs to land in the durable `game_events` log before the in-memory `MutableSharedFlow<GameEvent>` broadcast, transactionally with the state mutation, so server restart retains hand history and the in-memory `StateFlow<GameState>` becomes a derived view. V31 provisioned the table last cycle; this cycle wires the producer end of the pipeline.
**Approach:** Added `GameEventWriter` interface (with `NoOp` for tests) + `PostgresGameEventWriter` impl that writes the v1 `GameEventEnvelope` JSONB via a single transaction per intent (events from one engine call are all-or-nothing). `GameSession` got a UUID `id` + writer dependency; both `startHand` (and its private `requestNextHand`-driven `startHandLocked` sibling, lifted to `suspend`) and `applyIntent` now call `eventWriter.append(id, result.events)` *before* mutating `_state.value` or emitting to `_events` — the write-before-broadcast invariant the event-sourced architecture leans on. Writer failure: caught and returned as `IntentResult.Rejected("persistence failed: …")` with state untouched and no broadcast, so a DB blip looks to the client like a transient action-rejection rather than partial-state corruption. Also added a `jsonb(...)` Exposed column type in `:apps:server` because text→jsonb has no implicit Postgres cast — the writer wraps payloads in `PGobject(type="jsonb")` and reads pull `value` back out as `String`. **Rejected alternative:** wiring per-event (one transaction each) would risk partial-event log state if event N+1 fails mid-batch; batching all events from a single engine call is the cleaner invariant.
**Reviewer notes:** The crash-mid-hand replay equivalence test from the original B0 acceptance criterion is deferred — the replay function (event log → live `GameState`) doesn't exist yet and likely lands alongside B1's snapshot path. Rewrote the todo entry to slice that off as remaining work. The PK uniqueness + per-intent atomicity Postgres invariants are pinned by `(session_id, seq)` in the migration; an integration-test pin via `assertFailsWith<ExposedSQLException>` would not catch the throw cleanly across `newSuspendedTransaction`'s coroutine boundary (the exception leaks out to `runTest` even with a try/catch on the suspending caller) so the tests focus on the round-trip + isolation paths. `InMemoryGameSessionRegistry` constructor gained one required `GameEventWriter` arg — three test sites updated to pass `GameEventWriter.NoOp`. Direct test pre-existing failure: none on the suite I ran; full `:apps:server:test` is green including the Postgres-backed `PostgresGameEventWriterTest`.
**Deferred:** Replay-equivalence test (now its own B0 bullet in `docs/todo.md`). B0 sub-items B1 (snapshot compaction), B2 (WS reconnect upgrade), B3 (persisted room membership), B4 (event-sourced gameplay items) — all untouched and still in the todo. The `id: UUID` on `GameSession` is currently process-local (regenerated on each restart) — once B1 + B3 land, the registry will need to either persist a `room_code → session_uuid` mapping or promote sessions to a `sessions` table that the registry hydrates from at boot.

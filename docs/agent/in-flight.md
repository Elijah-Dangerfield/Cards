## refactor(room): migrate SeatTenure to resource-id shape

**Problem:** `SeatTenure.kt` owned six user-facing strings inline (singular/plural hand-count headline, human-vs-other supporting line, "Playing since {Month Year}" headline, the matching supporting line, and the 12 month names). The todo flagged it as deferred because the non-Composable `String` API had unit-test coverage on its formatters, and moving to `stringResource(...)` required either a Compose UI test runtime or a different shape.
**Approach:** Lifted the `tenureRows` function into a two-layer split that mirrors `BotPlayingStyle` / `BotDifficultyTier`: a pure `tenureSpecs(seat)` returns a sealed `TenureHeadline` family carrying `StringResource` references plus any numeric args (`HandsSingle`, `HandsMulti(count)`, `PlayingSince(monthResource, year)`); a thin `@Composable tenureRows(seat)` maps each spec into a `ListSectionItem`. Month names + `room_seat_tenure_*` keys live in `:libraries:resources/strings.xml`; the 12 calendar months use a generic `month_january`…`month_december` (+ `month_unknown` sentinel) family rather than a tenure-specific prefix, so any future Month-Year row can reuse them. `playingSinceComponents(epochMs)` and `monthResource(monthNumber)` stay non-Composable testable helpers. `SeatTenureTest` updated to assert on resource-id identity and sealed-variant equality — same pattern as `BotPlayingStyleTest`.
**Reviewer notes:** None — `./gradlew :features:room:impl:testDebugUnitTest` + `./gradlew :apps:compose:assembleDebug` both green. The only behavioral shift is that the headline-text assertions in the old test are now replaced by the sealed-variant + month-resource assertions on the pure helpers, which is the same correctness gate phrased structurally.
**Deferred:** `TableUiState.badgeFor()` — the other §A "deferred as its own slice" sibling. Same Composable-vs-pure tension, same fix likely applies; left in `docs/todo.md` for a later cycle so this commit stays one logical change. The "Playing since" headline currently passes the resolved month string as `%1$s` and the year as `%2$d` — that's `String.format`-style positional substitution, which Compose Multiplatform resolves consistently across Android + iOS today; no special handling needed.

## refactor(room): migrate SeatView.seatBadge to sealed SeatBadge

**Problem:** `TableUiState.Companion.badgeFor()` formatted three user-facing strings inline ("Lvl $level", "Bot · $label", "Bot") and stored them on `SeatView.seatBadge: String?`. The todo flagged it as the next deferred slice after `SeatTenure` — same non-Composable-vs-Composable tension, same trick applies.
**Approach:** Same shape as the `SeatTenure` migration that landed earlier this cycle. `SeatView.seatBadge` lifted from `String?` to a sealed `SeatBadge?` (`Level(level)` / `BotWithDifficulty(difficulty)` / `BotPlain`). `TableUiState.Companion.badgeFor()` returns the typed shape (still non-Composable, still pure). The renderer in `PlayerProfileSheet.kt` resolves via a new `@Composable SeatBadge.label()` extension that hits `stringResource(...)`. Bot-difficulty label stays a raw `String` because it's the wire-key from `SoloBotsPokerSessionFactory.difficultyName` (same call as the home `OptionPillRow` deferral). Resources: `room_seat_badge_level` (with %1$d), `room_seat_badge_bot_with_difficulty` (with %1$s), `room_seat_badge_bot_plain`. Visibility on `badgeFor` lifted from `private` to `internal` so the new test cases can hit it; otherwise the call site is identical.
**Reviewer notes:** None — `./gradlew :features:room:impl:testDebugUnitTest` + `./gradlew :apps:compose:assembleDebug` both green. `TableUiStateTest` extended with six new `badgeFor_*` assertions covering the four real variants plus the two null cases (empty seat, remote human in MP). The four `PlayerProfileSheet` preview helpers swap their inline `"Bot · Standard"` literals for `SeatBadge.BotWithDifficulty("Standard")` etc — same rendered text, typed source.
**Deferred:** Nothing room-side — with this commit every user-facing string in `:features:room:impl` either reads through `:libraries:resources` or stays inline only for the documented "wire-key / typography character / engine-output" reasons captured in the todo prose.

## feat(achievements): show "Earned" on the medallion front, not the XP reward

**Problem:** The Achievements grid renders the same "+X XP" reward label on every tile regardless of whether the user has earned it — so an earned tile and a locked target=1 tile look near-identical at a glance, undercutting the prestige signal the page is supposed to carry.
**Approach:** In `AchievementMedallion.kt`'s front layout, swap the reward label for the string `"Earned"` whenever `isEarned`. Locked quantitative tiles (`target > 1`) keep `"$progress / $target"` (the chase number); locked one-shot tiles (`target == 1`) keep `"+X XP"` (the "what you'd get" preview). The XP / chip reward number isn't lost — the medallion back still shows `+X XP · +Y chips`, accessible by tapping. Collapsed three near-identical Text branches into one `when` for the label.
**Reviewer notes:** No tests landed — the medallion has only `@Preview` coverage and the change is a pure label swap. Build + tests passed on Android; haven't yet exercised on iOS or hardware. The `Earned: {date}` caption from the todo bullet was deliberately deferred (needs a KMP relative-date formatter; out of scope for the at-a-glance fix). The "greyscale silhouette + lock glyph" alternative locked treatment also deferred — current alpha+gradient still reads as "faded but visible," which I judged a feature (the user can see the icon they're chasing) rather than a bug, but a designer might disagree.
**Deferred:** (a) "Earned: {date}" relative-date caption on the back — needs a small KMP date-format helper, no obvious home yet. Left as a comment in the todo bullet. (b) Locked-tile "greyscale silhouette" treatment — design call, left as a comment in the todo bullet.

## refactor(shop, profile): bump body-shaped subtitles from B400 to B500

**Problem:** Continuation of the typography audit RankDetailSheet kicked off — Shop and Profile still had body-shaped paragraphs declared at `Body.B400`, which by the StatsScreen / RankDetailSheet convention is for *captions* (labels, sublines, fine print), not body copy. Result: paragraph copy under each screen header reads visibly smaller than its body neighbours.
**Approach:** Walked Shop + ProfileScreen + PurchaseConfirmSheet and bumped only the callsites that are clearly body, not captions: `ShopHeader` subtitle, `SectionHeader` subtitle slot, `EmptyShop` paragraph, `StatusPrompt` body on `PurchaseConfirmSheet`, and `ClaimAccountCard` description on `ProfileScreen`. Left genuinely captional B400 callsites alone (per-product tile subtitles, "Charged via your <store>" fine print, `BalanceRow` labels, `ErrorBanner` message, shop snackbar inline text). Room/Home sweep still open — Room has the largest remaining concentration so I noted it on the todo bullet instead of doing it now (case-by-case caption-vs-body decisions across HandResultDialogs / HandRankingsCheatSheet / PlayerArea / RaiseSheet).
**Reviewer notes:** Pure typography swap, no behaviour change. No new tests — the convention is design-level. Build passes (`:features:shop:impl` and `:features:profile:impl` compile cleanly).
**Deferred:** Room/Home sweep — noted on the todo bullet. Worth a separate pass once one of those screens is next opened for a feature change.

## feat(achievements): show relative earned date on the medallion back

**Problem:** Follow-up to the front-side "Earned" label commit earlier tonight — the medallion back still said only "Earned" with no indication of *when*. The spec calls out "Earned: {date}" specifically as the prestige caption.
**Approach:** Added a tiny self-contained relative-time formatter `formatEarnedAgo(earnedAtEpochMs, nowEpochMs)` in `AchievementMedallion.kt` that returns "today" / "yesterday" / "Nd ago" / "Nw ago" / "Nmo ago" / "Ny ago" using bare `kotlin.time.Clock` arithmetic (no kotlinx-datetime dependency needed). Wired into the back-side header so it now reads "Earned · 3d ago". Composable-facing overload reads `Clock.System.now()`, test-facing overload takes `nowEpochMs` so the unit test pins behavior at exact bucket boundaries.
**Reviewer notes:** New `FormatEarnedAgoTest` covers each bucket transition (today/yesterday/d/w/mo/y) and the future-time clamp. The format is intentionally short ("3d", "2w") so it fits next to "Earned · " on the small medallion back without wrapping; can be loosened to "3 days ago" if a designer prefers the long form. Contradicts the deferral note I wrote in this same in-flight log earlier — that's because I overstated the difficulty of the formatter when deferring; the inline implementation is ~15 LOC.
**Deferred:** Locale-aware relative time (kotlinx-datetime + ICU) — way out of scope for a single-locale English V1. Backlog if/when localization is in play.

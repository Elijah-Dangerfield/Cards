## feat(achievements): show "Earned" on the medallion front, not the XP reward

**Problem:** The Achievements grid renders the same "+X XP" reward label on every tile regardless of whether the user has earned it — so an earned tile and a locked target=1 tile look near-identical at a glance, undercutting the prestige signal the page is supposed to carry.
**Approach:** In `AchievementMedallion.kt`'s front layout, swap the reward label for the string `"Earned"` whenever `isEarned`. Locked quantitative tiles (`target > 1`) keep `"$progress / $target"` (the chase number); locked one-shot tiles (`target == 1`) keep `"+X XP"` (the "what you'd get" preview). The XP / chip reward number isn't lost — the medallion back still shows `+X XP · +Y chips`, accessible by tapping. Collapsed three near-identical Text branches into one `when` for the label.
**Reviewer notes:** No tests landed — the medallion has only `@Preview` coverage and the change is a pure label swap. Build + tests passed on Android; haven't yet exercised on iOS or hardware. The `Earned: {date}` caption from the todo bullet was deliberately deferred (needs a KMP relative-date formatter; out of scope for the at-a-glance fix). The "greyscale silhouette + lock glyph" alternative locked treatment also deferred — current alpha+gradient still reads as "faded but visible," which I judged a feature (the user can see the icon they're chasing) rather than a bug, but a designer might disagree.
**Deferred:** (a) "Earned: {date}" relative-date caption on the back — needs a small KMP date-format helper, no obvious home yet. Left as a comment in the todo bullet. (b) Locked-tile "greyscale silhouette" treatment — design call, left as a comment in the todo bullet.

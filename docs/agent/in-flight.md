No unit tests added — this is preview-only visual work; the existing `PlayPokerViewModelTest` end-to-end flows still pass and would catch any regression on the `seat.stack <= 0` field flowing through to the SeatView, which is the only existing surface that this change reads.

## feat(table): collapse the chip stack when an opponent busts

**Problem:** The static `BustedStamp` shipped earlier on 2026-05-22 made the bust state legible at a glance, but the chip-stack number still snapped to "0" with no motion. The original `docs/todo.md § Animations / table polish` bullet called out the chip-collapse half explicitly: "a small animation when the stack number hits zero would land the moment harder than the static stamp alone."
**Approach:** Wrap the `ChipCoinAmount` inside `OpponentSeat` in a ColumnScope `AnimatedVisibility(visible = !busted)`. Exit composition is `fadeOut(280ms) + slideOutVertically(it, 360ms) + shrinkVertically(360ms)` — the stack reads as falling away from the seat while the surrounding column flow collapses cleanly thanks to ColumnScope's `shrinkVertically`. Enter is the symmetric short tween (220ms fadeIn + slideInVertically from above + expandVertically), so a bot rebuy on the next hand slides the new stack in rather than popping it. No new DS primitives needed — `AnimatedVisibility` + the existing `ChipCoinAmount` is enough; the "collapse" is a layout-and-motion call, not a render-pipeline one.

## feat(table): swipe-up-to-fold on the human's hole cards

**Problem:** `docs/todo.md § Table-side social` listed swipe-up-to-fold as a V1 gesture but it had no implementation. Today the only way to fold is via the "more options" sheet behind the ↑ button on the action bar — a two-tap path on what's the most common destructive action of the hand. The spec calls for the gesture to be *discoverable* (a confirmation dialog the first time) and then *out of the way* (silent fold once acknowledged).
**Approach:**
- `AppData.swipeFoldGestureAck: Boolean = false` records whether the user has dismissed the confirmation dialog with "Don't show this again". New field, default = false, kotlinx-serialization compatible (existing on-disk caches load without migration).
- `PlayerArea` gains an `onSwipeFold: () -> Unit` callback and applies `Modifier.pointerInput(swipeFoldEnabled, thresholdPx) { detectVerticalDragGestures { ... } }` to the hole-cards Box. Gate is `table.isHumanTurn && humanLegalActions != null && participation != Folded`. Threshold is 60dp of cumulative upward `dy` (about half the hole-card height of 142dp); first crossing of the threshold mid-drag fires `HapticFeedbackType.LongPress` + `onSwipeFold` (and sets a `fired` latch so a single continuous drag doesn't double-fire). Drag-end / cancel resets the latch.
- `PlayPokerState.swipeFoldGestureAck` mirrors `AppData` via the existing `appCache.updates` collector in `PlayPokerViewModel.init`. Two new `PlayPokerAction`s: `SwipeFoldAckChanged(value)` (mirror) and `AcknowledgeSwipeFoldGesture` (writes `AppCache.update { it.copy(...) = true }`).
- `PlayPokerScreen` owns the dialog gate via a local `var swipeFoldConfirmOpen by remember`. On `onSwipeFold` from `PlayerArea`: if the ack flag is true, dispatch `Submit(PlayerIntent.Fold(humanIndex))` immediately; else open the dialog. The dialog (`SwipeFoldConfirmDialog`, new file) has Cancel + Fold pills + a "Don't show this again" checkbox (default checked) — confirming with the box ticked fires `AcknowledgeSwipeFoldGesture` + the Fold intent in one go.
- Tests: `appCacheEmission_mirrorsSwipeFoldGestureAck` pins the AppCache → state mirror; `acknowledgeSwipeFoldGesture_writesThroughToAppCache` pins the round-trip through the FakeAppCache.
**Reviewer notes:** The new dialog file (`SwipeFoldConfirmDialog.kt`) is structurally a clone of `LeaveBotsConfirmDialog` — same `Dialog + dialogEmoji + ConfirmPill` shape — with a checkbox row added. The two could share a `ConfirmPill` primitive, but extracting now feels like premature abstraction (LeaveBotsConfirmDialog is the only other caller and the pill style is identical). If a third caller appears, lift it to `:libraries:ui`. The pointerInput modifier captures `LocalHapticFeedback` at composition time (inside the `with(LocalDensity.current) { ... }` block) — this is fine because the haptics interface is stable and recomposition will re-launch the pointerInput effect (the modifier's `key2` is `swipeFoldEnabled`, which already shifts every turn so the gesture detector restarts cleanly). The 60dp threshold was picked from "half the hole-card height" — the user has 142dp of card to swipe over and 60dp is a comfortable thumb-distance without being trivially triggerable; the existing `Dimension` tokens don't have a great fit, so left as a raw `60.dp` literal at the callsite with the rationale in the in-flight notes. Swipe gate intentionally checks `participation != Folded` so a re-fold during the same hand doesn't trigger (you can't fold twice).
**Deferred:** None. The chip-flow / animation polish around the fold itself (card-fly-away animation when the swipe fires, for instance) isn't in the original bullet and would be its own task; not added to backlog because the visual feedback we have now (haptic + Folded participation state → existing dimmed hole cards) reads cleanly.

## refactor(ui): route Material icon callsites through DS

**Problem:** AppGuardLayer (maintenance Warning), OfflineBanner (CloudOff), and OnboardingScreen (Edit, Lock) were reaching past the DS to `androidx.compose.material3.Icon` + `androidx.compose.material.icons.Icons.*`, leaking Material defaults into screens that otherwise honor the DS.
**Approach:** Replace each Material call with the DS `Icon(icon = Icons.X(desc), size, color)`. Reused existing DS entries (`Warning`, `Pencil`, `Lock`) and added one new entry `CloudOff` (mapped to `Icons.Default.CloudOff`) to `:libraries:ui:components:icon:Icons` rather than hand-tuning the offline banner. Sizes snap to the nearest existing `IconSize` token (`Smallest`/`Small`); colors swap from raw `Color` to the corresponding `ColorResource` so the DS contract carries through.
**Reviewer notes:** OnboardingScreen's display-name `OutlinedTextField.trailingIcon` was hand-tuned to `18.dp` — closest DS token is `IconSize.Small` (`D800` = 20dp); 2dp upsize is the visible delta. Avatar-edit pencil and "more packs" lock were already at 14dp = `IconSize.Smallest`, exact match. Builds: `:apps:compose:assembleDebug` + `:apps:compose:compileKotlinIosSimulatorArm64` both green.
**Deferred:** `:libraries:ui`-internal `FeatureCard.kt` still imports Material `Icon` directly — that's DS authoring and the todo carve-out (`Out of scope: redesigning the DS icon set`) is ambiguous about it; left for the next pass. Stats info-button is also still on Material per the todo's call-out; left for a separate commit since it pairs with the upcoming Stats refactor.

## refactor(room): migrate PotPill + WinOddsBadge to felt-accent surface

**Problem:** PotPill (BoardArea) and WinOddsBadge sit directly on the table felt but hardcoded `AppTheme.colors.surfaceSecondary`, so on non-default felts they read as alien chrome pasted on a colored background instead of "raised felt."
**Approach:** Wire both to `LocalFeltAccentSurface.current` with a fallback to `surfaceSecondary.color`, mirroring the pattern already used by `QuickActionBar`'s "more raise options" `IconButton`. Pure background swap — no layout change.
**Reviewer notes:** Visual change only; verifiable in Studio via `BoardAreaPreview_*` / `WinOddsBadgePreview_*` (those run with the default felt, so the previews look identical — felt-aware behavior only kicks in inside `PlayPokerScreen` where the local is provided). The todo's other felt-aware candidates (opponent chrome, explainer drag handles) are still open and remain in `docs/todo.md` under §A.
**Deferred:** OpponentsRow + explainer-sheet drag handle sweeps — todo updated to narrow the remaining surface to those two areas; another worker can pick them up.

## refactor(ui): migrate FeatureCard ChevronRight to DS Icon

**Problem:** `FeatureCard.kt` (a public `:libraries:ui` component used for primary CTAs on tab screens) was the last Material-icon callsite in the repo — it imported `androidx.compose.material3.Icon` + `Icons.Default.ChevronRight` directly. The prior icon-migration sweep deferred it as DS-internal authoring; the todo bullet specifically flagged it as "DS-internal use is fine but worth a pass."
**Approach:** Replace the Material call with `Icon(icon = Icons.ChevronRight(null), size = IconSize.Medium, color = AppTheme.colors.text)`. `IconSize.Medium` = `D900` = 24 dp, exact match for Material's `Icon` default, so no visual delta. `Icons.ChevronRight` was already in the DS enum — no new entry needed. After this commit, no `:libraries:ui`-external code reaches past the DS for icons; the only remaining Material `Icon` callsites are the DS Icon-wrapper functions themselves (`Icon.kt`) and the in-file preview grid (`Icons.kt` line 348) — both DS authoring. Removed the bullet from `docs/todo.md` (`§A · DS consistency · Stop reaching past the DS for Material primitives`) because both call-outs in it are now resolved: `FeatureCard.kt` is migrated and the "Stats info-button on Material" call-out is stale (Stats already uses the DS `IconButton(icon = Icons.Question(...))`).
**Reviewer notes:** Visual delta is zero — Material's `Icon` default size is 24 dp and `IconSize.Medium` resolves to the same; tint maps from `AppTheme.colors.text.color` (raw `Color`) to `AppTheme.colors.text` (`ColorResource`), same color underneath. Verified via `:libraries:ui:compileDebugKotlinAndroid`, `:libraries:ui:testDebugUnitTest`, and `:apps:compose:assembleDebug` — all green.
**Deferred:** None.

## refactor(room): route EmojiPickerRow through felt-accent surface

**Problem:** The in-game emoji-blast popup (`EmojiPickerRow`, anchored to the play-screen TopBar) painted its `Surface` background with `AppTheme.colors.surfaceSecondary`, so on non-default felts the picker chrome read as an alien chip pasted on a colored background instead of as "raised felt." This was the last play-screen-over-the-felt candidate from the §A felt-aware sweep todo — the other listed candidates (opponent seat chrome, explainer-sheet drag handles) don't actually surface `surfaceSecondary` on the felt: `OpponentsRow` children paint `surfaceTertiary` (LastActionPill) or no background at all, and `HandRankingsCheatSheet` uses `BottomSheetDragHandle.None`. With this commit, every `Box`/`Surface` painting `surfaceSecondary` directly on the felt is migrated, so I removed the bullet (and its now-empty `### Felt-aware play-screen chrome` heading) from `docs/todo.md`.
**Approach:** Read `LocalFeltAccentSurface.current` and pass it to a new `colorOverride` parameter on the non-clickable `Surface` overload (the clickable overload already had one; this matches the established pattern from `IconButton.backgroundOverride` / `TableActionBar`'s "more raise options" icon button). When felt accent is non-null, pass `color = null` to skip the DS-token paint and let `colorOverride` win. Outside the play screen the local resolves to `null`, so the picker still renders with `surfaceSecondary` everywhere else — a no-op for any preview / non-table context.
**Reviewer notes:** `EmojiPickerRowPreview` runs without `LocalFeltAccentSurface` provided, so it still renders on `surfaceSecondary` — felt-aware behavior is only visible inside `PlayPokerScreen`. The new `colorOverride` on the non-clickable `Surface` is parameter-additive (default `null`); the existing clickable overload already shipped it, so this just closes the symmetry gap. `:apps:compose:assembleDebug` + `:libraries:ui:test` + `:features:room:impl:testDebugUnitTest` all green.
**Deferred:** None — felt-aware sweep is fully cleared.

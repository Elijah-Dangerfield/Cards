## feat(home): reactive active-room banner via observeActiveRooms flow

**Problem:** Home's active-game banner read from a one-shot `getActiveRooms()` on init/refresh, so it went stale until something re-triggered the fetch — a forfeit or a join elsewhere didn't reflect live.
**Approach:** Added `RoomRepository.observeActiveRooms(): Flow<List<Room>>`, backed by an in-memory `MutableStateFlow` in `RoomRepositoryImpl` that's seeded by `getActiveRooms()` and kept current by the local create/join/leave mutations (join upserts, leave/not-found/not-in-room removes). `HomeViewModel` now subscribes to it (pure projection: newest room → banner) instead of one-shot fetching; the seed `getActiveRooms()` runs in its own init launch, NOT through the action pipeline, because calling it inside `handleAction` drives the same collector re-entrantly and strands the emission under the unconfined test dispatcher. Forfeit dropped its optimistic state mutation — the leave clears the banner via the flow on success and correctly leaves the room visible on failure (no re-query needed). Chose a client-side projection over wiring the durable server source now: the durable/server-pushed source is gated on B2 (persisted membership), and the client projection already satisfies the "reflect my own join/forfeit live" case the item is about. Sliced the todo to the remaining off-device-reflection gap.
**Reviewer notes:** **Scope cut — dropped the proactive multi-room stale-leave.** The old `reconcileToSingleRoom` auto-left every room but the newest when >1 active room slipped through. Reactively re-issuing those leaves fed back through the same observed flow and deadlocked the consumer under `UnconfinedTestDispatcher` (the leave synchronously mutates the StateFlow the collector is on). I kept the *user-visible* behavior — the banner still shows exactly the newest room via a pure projection — but no longer proactively leaves the stale ones; the server's seat-grace timer reaps them. If we want the proactive leave back, it belongs server-side or behind a non-reentrant one-shot, not on the reactive path. The home test fake's `getActiveRooms`/`leaveRoom` now `yield()` before mutating the observed flow to mirror a real network round-trip (synchronous mutation under unconfined is what caused the reentrancy). Tests: home VM (incl. new `liveUpdate_reflectsWithoutRefetch`, rewritten `forfeit_networkError_keepsRoomVisible`), `RoomRepositoryImpl` flow seeding/leave/join, lobby + room fakes updated for the new interface method. `:apps:compose:assembleDebug` green.
**Deferred:** Off-device room-change reflection (host closes room elsewhere, server-side forfeit) — needs the durable source; rewritten into the todo bullet, gated on B2.

## feat(room): call out cosmetic unlocks in the achievement callout

**Problem:** §A "Wire the earned-grant path" had a `**Client:**` sub-bullet asking for a "celebratory unlock dialog at the moment of earning — prestige lives at earn-time, not on the shelf." Today an EPIC achievement that grants `cardback_comeback_kid` (or any of the four allowlisted cosmetics) silently drops the row into inventory via the server's `POST /v1/me/grants/achievement/{id}` and the sync. The user sees the achievement callout in the showdown / bust dialog, then later finds the cosmetic in My Items with no thread tying the two together.
**Approach:** Two-file change, no plumbing changes. New [EarnableCosmetics.kt](../../libraries/cards/src/commonMain/kotlin/com/cards/libraries/cards/EarnableCosmetics.kt) ships a `cosmeticRewardFor(AchievementId): CosmeticReward?` mirror of the server's `ClientGrantableAchievements.Default` map (server stays authoritative for the grant; the client only needs the mapping to *name* the cosmetic in the UI). `AchievementUnlockedCallout` in [HandResultDialogs.kt](../../features/room/impl/src/commonMain/kotlin/com/cards/features/room/impl/HandResultDialogs.kt) now renders an inline "🎁 Also unlocked · {label}" row whenever the earned achievement has a cosmetic mapping. New [EarnableCosmeticsTest.kt](../../libraries/cards/impl/src/commonTest/kotlin/com/cards/libraries/cards/impl/EarnableCosmeticsTest.kt) pins all four current mappings + spot-checks the no-reward path. Updated `docs/todo.md` to flag the bullet as partially landed with the remaining "dedicated full-bleed dialog after dismiss" work called out explicitly.
**Reviewer notes:** I deliberately picked the smaller of the two options. The bullet says "dialog" and "prestige lives at earn-time", which suggests a dedicated full-screen celebration sequenced after the showdown dismisses; doing that would have cut into VM action sequencing + animation work that pairs with the "XP / coin earned distribution animation" bullet, which itself is queued. Shipping the inline row first delivers the missing acknowledgement of the cosmetic *now* and the dedicated dialog becomes a follow-up enhancement rather than a from-scratch ask. The mapping table on the client is a duplicate of the server's allowlist — the test will fail loudly if either side drifts, and the file's KDoc points at the server source of truth so the next worker who touches one finds the other.
**Deferred:**
- The dedicated full-bleed unlock celebration (the "promote it from a row to a dedicated, full-bleed unlock celebration that sequences *after* the hand-result dialog dismisses" line is now on `docs/todo.md` under the same bullet, so reviewer doesn't need to triage further).

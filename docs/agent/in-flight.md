## feat(server): emit room_code as Loki structured metadata on room routes

**Problem:** MP triage during the 2026-06-22 feedback batch had to brittle-line-grep Loki because room-route logs carried no room code; a long-lived socket coroutine's `session_id` is just whoever currently holds it (a bot has none), so it can't pivot a whole room.
**Approach:** Parse the room code from the request path on room routes, uppercase it to match the handlers' normalized code + the span `room.code` attribute, and seed it into the CallLogging MDC. The OTel logback appender already forwards all MDC keys (`captureMdcAttributes=*`), so it lands as Loki structured metadata with no logback change. Chose structured metadata over a stream label because a room code is unbounded high-cardinality and a Loki label would explode the index — `{service_name="cards-server"} | room_code="<CODE>"` stays cheap. Also corrected the feedback-triage skill's Loki guidance (these correlation fields are matched with the label-matcher pipe `| session_id=`, not a line filter `|=` which silently matches nothing).
**Reviewer notes:** Pre-existing commit reconstructed from its message — I did not re-verify it at runtime this cycle. The MDC-key forwarding assumption (`captureMdcAttributes=*`) is the load-bearing part; worth a glance.

## fix(server): bots-only MP hand earns no "Took a seat" credit

**Problem:** The MP achievement "Took a seat" (and the rest of the server-witnessed MP achievements) fired even in a bots-only room — a lone human plus bots — when the owner wanted them gated to real opponents (feedback CARDS-W).
**Approach:** Gated `DefaultGameSessionRegistry.recordHandsFinished` on `outcome.perHuman.size >= 2`. The MP achievements are *server-witnessed*: they key off `HandsFinishedRepository.countForUser`, and the registry was ticking that count for the lone human in a bots-only room, so `FIRST_HAND_MP` granted at count 1. Bots never enter `HandOutcome.perHuman`, so its size is exactly the human count; `< 2` means bots-only/solo, so we skip the finished-hand witness + both server-witnessed evals. Mirrors the 2-human floor `recordRecentOpponents` already applied, so recents and achievements now agree on what counts as a real opponent. Chose the registry gate over a client-side achievement gate because the credit is wholly server-derived — gating the client would leave the server count drifting upward and re-granting on the next sync.
**Reviewer notes:** This also (correctly) stops `HANDS_100_MP` and the per-hand-shape MP achievements (double-up, pot-5000, busts-dealt) from accruing in bots-only rooms — same "no MP credit vs bots" principle, all witnessed off the same finished-hand ledger. The client-side `HandResultSummaryBuilder` already downgrades bots-only MP hands to `XpMode.BOTS` (so client-witnessed MP achievements were already gated); this closes the server-witnessed half. Added `finishedHand_botsOnlyTable_doesNotWitnessCountOrAchievements` to `GameSessionRegistryIntegrationTest` (passes).

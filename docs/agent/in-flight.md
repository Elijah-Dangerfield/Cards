## fix(room): format chip amounts in action labels (pill, action bar, explainer)

**Problem:** Three chip-amount surfaces around the play screen's action affordances still rendered raw `${amount}` interpolation, drifting from the `formatThousands` / `formatCompactChips` polish the prior worker landed on the achievement-reward and pot-pill surfaces: (1) [`PlayerAction.shortLabel()`](../../features/room/impl/src/commonMain/kotlin/com/cards/features/room/impl/TableUiState.kt) — feeds the seat-side [`LastActionPill`](../../libraries/ui/src/commonMain/kotlin/com/cards/libraries/ui/components/poker/LastActionPill.kt) on every opponent and the human — was emitting `"Called 5000"` / `"Raised to 12345"`, which sits awkwardly next to the `5k` / `12k` formatting already used by the seat stack ([PlayerArea.kt:568](../../features/room/impl/src/commonMain/kotlin/com/cards/features/room/impl/PlayerArea.kt#L568)) and the pot pill ([BoardArea.kt:187](../../features/room/impl/src/commonMain/kotlin/com/cards/features/room/impl/BoardArea.kt#L187)); (2) [`LastActionExplainer`](../../features/room/impl/src/commonMain/kotlin/com/cards/features/room/impl/LastActionExplainer.kt) — the tap-the-action-pill dialog headline — read `"Jane called 5000"`; (3) the [`TableActionBar`](../../features/room/impl/src/commonMain/kotlin/com/cards/features/room/impl/TableActionBar.kt) Call / Bet / Raise buttons rendered `"Call 5000"` / `"Bet 12345"`. None of these are wrong at standard-stake bot tables (numbers stay small), but the upcoming MP buy-in mechanic on `docs/todo.md` §B unlocks larger stacks where a `"Bet 25000"` button reads as a wall of digits.
**Approach:** Picked the formatter per surface to match the surrounding UI:
- `shortLabel()` and the action-bar buttons → `formatCompactChips` (e.g. `Called 5k`, `Bet 1.5k`, `All in 1M`). Same compact form the seat stack and pot pill already use; keeps the pill / button width steady at high stakes.
- `LastActionExplainer` headline → `formatThousands` (e.g. `Jane called 5,000`). Dialog has horizontal room and the user opened it specifically to confirm the precise number, so the comma-grouped form reads more honestly than `5k`.

Tests: new `shortLabel_compactlyFormatsChipAmounts` case on [TableUiStateTest](../../features/room/impl/src/commonTest/kotlin/com/cards/features/room/impl/TableUiStateTest.kt) pins each branch — small (`Called 20`), thousands (`Bet 500`, `Raised to 1.5k`), tens-of-thousands (`All in 12k`), and millions (`Called 1M`) — so a future change to `formatCompactChips` thresholds doesn't silently shift this surface.

**Reviewer notes:** Two formatters in one commit is deliberate — the pair of decisions (`compact` for tight surfaces, `thousands` for the wide dialog) belongs together as one judgement call rather than split across two commits. Kept the explainer's `All in` headline as `"$seatName went all in"` (no amount) since the action's "drama" is the all-in *event*, not the specific stack size; the pill still shows `All in 12k` because that surface is the ambient signal where the amount matters. If a designer wants the dialog to surface the all-in amount, it's a two-line add.

## refactor(cards): centralize formatThousands as a shared utility

**Problem:** Four copies of the same thousands-separator number formatter were drifting across the codebase — [ChipBadge.kt](../../libraries/ui/src/commonMain/kotlin/com/cards/libraries/ui/components/ChipBadge.kt) (`internal fun formatThousands`), [ProfileScreen.kt](../../features/profile/impl/src/commonMain/kotlin/com/cards/features/profile/impl/ProfileScreen.kt) (`private fun formatThousands`), [StatsScreen.kt](../../features/progression/impl/src/commonMain/kotlin/com/cards/features/progression/impl/StatsScreen.kt) (`private fun formatThousands` — and this one had an extra `if (s.length <= 3) return s` short-circuit), and [ShopComponents.kt](../../features/shop/impl/src/commonMain/kotlin/com/cards/features/shop/impl/ShopComponents.kt) (`internal fun formatChips`). All four implementations were near-identical for positive values; two of them had subtly broken negative-number handling (`formatThousands(-100L)` rendered as `"-,100"` because the iteration treated the leading `-` as a digit position).
**Approach:** Added [`formatThousands(value: Long)`](../../libraries/cards/src/commonMain/kotlin/com/cards/libraries/cards/NumberFormatting.kt) to `:libraries:cards` — comma-separated output, correct negative handling via an explicit sign flag (so `-1,000` and `-12,345` round-trip the test suite cleanly). Migrated the four duplicates to import + use the shared one. Shop's `formatChips` stays as an `internal` re-export so the shop callsites keep their familiar name; the body just delegates. Default formatter for [`AnimatedNumberText`](../../libraries/ui/src/commonMain/kotlin/com/cards/libraries/ui/components/AnimatedNumberText.kt) + [`ChipCoinAmount`](../../libraries/ui/src/commonMain/kotlin/com/cards/libraries/ui/components/ChipCoin.kt) now resolves through the shared import. New [NumberFormattingTest.kt](../../libraries/cards/impl/src/commonTest/kotlin/com/cards/libraries/cards/impl/NumberFormattingTest.kt) pins the boundary cases — below-1000 (no comma), at/above 1k/1M (insert commas at the right offsets), negatives across all magnitudes.
**Reviewer notes:** Chose `:libraries:cards` over `:libraries:core` as the home because the function's primary users are chip / XP / hand-count surfaces that already pull from `:libraries:cards`; `:libraries:core` would have needed an extra module-graph hop from `:libraries:ui` and the existing `Catching` neighborhood there is a different concern entirely. Named it `formatThousands` (not `formatChips`) to match the three existing local-copy callsites and avoid implying chip-specific semantics — XP totals on StatsScreen / ProfileScreen pass through the same formatter. Compact-format use cases (`12k` / `1.2M`) still belong on the existing [`formatCompactChips`](../../libraries/ui/src/commonMain/kotlin/com/cards/libraries/ui/components/ChipBadge.kt) — the KDoc on the new function calls that out explicitly so future readers don't have to guess which to pick.

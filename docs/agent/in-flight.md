## test(gameplay): property-based engine invariants (B6 Round 3)

**Problem:** B6 Round 3 — the gameplay engine is pure and load-bearing but shipped with only crafted-deck scenario tests; the testing plan calls for property-based invariant pins (no chip created/destroyed, monotonic sequences, scrub never leaks, etc.) that no single scenario test can guarantee.
**Approach:** Added `GameEnginePropertyTest` — a deterministic random-*legal*-action driver plays 300 seeded full hands across 2–6 seats, mixed stacks (40/80/200/1000 → forces side pots + all-ins), and varying button positions, asserting six invariants at every step: stack conservation, strict sequence monotonicity (+ final `lastSequence`), acting-seat-always-canAct (null iff Complete), settlement==contributed, pot conservation + nested side-pot eligibility, and hole-card scrub non-leakage (incl. `-1` spectator). **Direction call:** ran property tests in plain `kotlin.test` rather than adopting the plan's suggested `kotest-property` — it keeps the suite multiplatform (no JVM-only split), adds zero dependencies/version-catalog churn, and the engine's determinism-given-a-seed makes a hand-rolled seeded driver reproduce failures exactly. The rejected alternative (kotest-property) buys nicer shrinking but at the cost of a new dep and a source-set split this module doesn't otherwise need.
**Reviewer notes:** The driver's `chooseLegalIntent` mirrors `GameEngine.resolveAction`'s legality rules — if engine legality drifts, these tests surface it as an `IllegalArgumentException` rather than a silent pass, which is the intended tripwire. The pot-eligibility invariant asserts the *sound* nested/conservation/in-hand form, not exact per-tier membership; exact 3-way side-pot eligibility stays pinned by `GameEngineAdvancedTest`. Round 3's cross-product table tests, edge-case scenarios, and hand-history fixtures are still open — Round 3 marked "in progress" in the plan's tracking table, B6 stays on the list.
**Deferred:** Remaining Round 3 work (cross-product action tables, named edge scenarios, 50-hand history fixtures), plus Rounds 2 / 5 / 6 — all noted in `testing-plan.md`; reviewer please triage ordering against feature work.

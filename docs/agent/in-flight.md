## test(cards): pin cosmeticSlotFor + isPersonalCosmetic helpers

**Problem:** `:libraries:cards/CosmeticCategory.kt` carries two pure utilities — `cosmeticSlotFor(productId)` and `isPersonalCosmetic(productId)` — that the shop's auto-equip-on-purchase rule and the My Items "Only visible to you" badge both depend on. Drift between the prefix-string switchboard here and the server-side product-id conventions in `V5__products.sql` / V7 / V43 would silently misclassify cosmetics — the shop would either fail to auto-equip a felt or label a public title as personal-only. Both are silent UX bugs that escape compilation.
**Approach:** new `CosmeticCategoryTest` in `libraries/cards/src/commonTest`. Covers every documented prefix mapping (`felt_*` and `table_*` → Felt; `cardback_*` → CardBack; `title_*` → Title; `tool_*` → Tool; `badge_*` → Badge) using real product ids from the current catalog so the assertions break loudly if a prefix gets renamed. For `isPersonalCosmetic` pins the Felt / CardBack / Tool → true and Title / Badge → false rules plus the unknown-id default of public. 16 test cases — mechanical but each anchors one switchboard branch so a future "I'll just add another prefix" edit can't silently broaden personal-cosmetic coverage to a public-visible slot. **Source:** worker-hydrated this cycle (not human-curated). Hydrated under Lane A "Tests pinning load-bearing prefix-mapping utilities" right before shipping per the worker-hydrator override; no `docs/todo.md` entry was added since the item shipped end-to-end in one commit.
**Reviewer notes:** test-only, no production code touched. `:libraries:cards:allTests` passes on both JVM and iosSimulatorArm64.
